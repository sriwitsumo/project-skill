# วัตถุประสงค์ — คู่มือเจาะลึก

## หน้าที่ของหัวข้อนี้ (และห้ามทำอะไร)

ตอบคำถามเดียว: **"ทำโครงงานนี้เพื่อบรรลุอะไรบ้าง"** เขียนเป็นรายการข้อ ๆ สั้น กระชับ วัดผลได้

**ห้าม**:

- ห้ามอธิบายเหตุผล/ที่มาว่าทำไมถึงตั้งวัตถุประสงค์นี้ (อธิบายไปแล้วในที่มาฯ) แค่ระบุ "อะไร" ไม่ต้องพูด "ทำไม" ซ้ำ
- ห้ามอธิบายวิธีการทำงานแบบละเอียด (เช่น "เพื่อสร้างเครื่องรดน้ำที่ใช้เซนเซอร์ DHT22 ต่อกับ Arduino ผ่านโปรโตคอล I2C...")
  — วัตถุประสงค์บอกแค่ "จะทำอะไร" ไม่ใช่ "ทำอย่างไร" รายละเอียดวิธีการไปอยู่ขอบเขต/วิธีดำเนินงาน (บทที่ 3)
- ห้ามเขียนสิ่งที่เป็นผลลัพธ์ปลายทางระยะยาวเกินขอบเขตที่โครงงานนี้ควบคุมได้ (เช่น "เพื่อลดปัญหาขยะพลาสติก
  ของประเทศไทย" ทั้งที่โครงงานทำแค่ในโรงเรียนแห่งเดียว) — ถ้าอยากพูดถึงผลกระทบวงกว้าง ให้ใส่ในหัวข้อ
  ประโยชน์ที่คาดว่าจะได้รับแทน โดยใช้คำที่บ่งบอกว่าเป็นความคาดหวัง ไม่ใช่เป้าหมายที่วัดผลได้ตรง ๆ

## กฎเหล็ก: จำนวนข้อต้องล้อกับที่มาความสำคัญ

วัตถุประสงค์แต่ละข้อต้อง **ตอบสนองปัญหาที่ยกมาในหัวข้อที่มาฯ โดยตรง** วิธีตรวจสอบที่ได้ผลที่สุดคือไล่ทวน
ย้อนกลับ: อ่านวัตถุประสงค์แต่ละข้อ แล้วถามว่า "ข้อนี้แก้ปัญหา/ช่องว่างข้อไหนที่พูดไว้ในที่มาฯ" ถ้าตอบไม่ได้
แปลว่าวัตถุประสงค์ข้อนั้น "ลอย" ไม่มีที่มา ต้องตัดทิ้งหรือย้อนกลับไปเพิ่มเหตุผลในที่มาฯ ก่อน ในทางกลับกัน
ถ้าที่มาฯ พูดถึงปัญหาไว้แต่ไม่มีวัตถุประสงค์ข้อไหนมาตอบ ก็แปลว่าเขียนตกหล่น

ไม่จำเป็นต้อง 1 ปัญหา : 1 วัตถุประสงค์เป๊ะเสมอไป (บางครั้ง 1 วัตถุประสงค์ตอบได้หลายปัญหาพร้อมกัน) แต่ห้าม
มีวัตถุประสงค์ข้อไหนที่ไม่มีรากมาจากที่มาฯ เลย

## รูปประโยคมาตรฐาน

วัตถุประสงค์ภาษาไทยเขียนด้วยรูปประโยคเดียวเสมอทั้งเล่ม เพื่อความเป็นระเบียบ:

```
เพื่อ + [กริยา] + [กรรม/สิ่งที่ทำ] + [รายละเอียดเสริมสั้น ๆ ถ้าจำเป็น]
```

**ตัวอย่างกริยาที่ใช้บ่อยและความหมายที่ต่างกัน (เลือกให้ตรงกับสิ่งที่ทำจริง อย่าใช้มั่ว)**:

| กริยา | ใช้เมื่อ | ตัวอย่าง |
|---|---|---|
| ศึกษา | ต้องการทำความเข้าใจ/หาความรู้ ยังไม่ได้ลงมือสร้างอะไร | เพื่อศึกษาปัจจัยที่มีผลต่อ... |
| ออกแบบและสร้าง / พัฒนา | ลงมือสร้างสิ่งประดิษฐ์/ระบบ/โปรแกรมขึ้นจริง | เพื่อออกแบบและสร้างเครื่อง... / เพื่อพัฒนาเว็บแอปพลิเคชัน... |
| ทดสอบ / เปรียบเทียบ | ต้องการวัดประสิทธิภาพของสิ่งที่สร้าง หรือเทียบวิธีการหลายแบบ | เพื่อทดสอบประสิทธิภาพของ... / เพื่อเปรียบเทียบ...ระหว่าง...กับ... |
| สำรวจ / รวบรวม | เก็บข้อมูลที่มีอยู่แล้วในธรรมชาติ/สังคม ไม่ได้สร้างอะไรใหม่ | เพื่อสำรวจความคิดเห็นของ... / เพื่อรวบรวมข้อมูล... |
| วิเคราะห์ | ต้องการหาความสัมพันธ์/แยกแยะข้อมูลที่มีอยู่ | เพื่อวิเคราะห์ความสัมพันธ์ระหว่าง...กับ... |
| ประยุกต์ใช้ | นำองค์ความรู้/เทคโนโลยีที่มีอยู่แล้วมาใช้ในบริบทใหม่ | เพื่อประยุกต์ใช้ [เทคโนโลยี] ในการแก้ปัญหา... |

**ข้อผิดพลาดที่พบบ่อย**: ใช้ "เพื่อศึกษาและสร้าง..." พร่ำเพรื่อทั้งที่จริง ๆ โครงงานไม่ได้มีขั้นตอนศึกษาทฤษฎี
เป็นเรื่องเป็นราวก่อนสร้าง (ทุกโครงงานย่อมต้องศึกษาข้อมูลมาก่อนอยู่แล้วเป็นเรื่องปกติ ไม่จำเป็นต้องระบุคำว่า
"ศึกษา" ซ้ำในทุกข้อ) ให้ใช้กริยาที่ตรงกับ "แก่นของสิ่งที่ทำจริง" ของแต่ละข้อแทน

## ความยาวและจำนวนที่เหมาะสม

**ข้อกำหนดขั้นต่ำ (บังคับ): ต้องมีอย่างน้อย 3 ข้อ** เว้นแต่ผู้ใช้/สถาบันระบุไว้ชัดเจนเป็นอย่างอื่น ถ้าร่างแรกออกมา
ได้แค่ 1-2 ข้อ ห้ามปล่อยไว้แค่นั้น ให้กลับไปพิจารณาว่า "สร้าง/พัฒนา" กับ "ทดสอบ/ประเมินผล" ถูกแยกเป็นคนละ
ข้อแล้วหรือยัง (มักนับเป็น 2 ข้อได้อยู่แล้วในโครงงานส่วนใหญ่) แล้วดูว่ามีมิติอื่นที่ยังไม่ถูกพูดถึงหรือไม่ เช่น มิติ
เปรียบเทียบกับวิธีเดิม มิติความพึงพอใจของผู้ใช้งาน หรือมิติของกลุ่มเป้าหมายที่ยังไม่ได้แตะ — ห้ามเติมข้อที่ 3
ด้วยการแยกรายละเอียดย่อยของข้อเดิมออกมาเป็นข้อใหม่เทียม ๆ เพราะจะกลายเป็นข้อที่ซ้ำแก่นกับข้ออื่น

งานวิจัยระดับสูงอาจมี 3-5 ข้อ ถ้าเกิน 5-6 ข้อ มักเป็นสัญญาณว่าบางข้อสามารถรวมกันได้ หรือบางข้อจริง ๆ แล้ว
เป็นรายละเอียดย่อยของข้อใหญ่ (ให้รวมเป็นข้อเดียวแล้วใช้ "โดย" ขยายความ เช่น "เพื่อพัฒนาเครื่อง... โดยให้
สามารถ...")

เรียงลำดับข้อจากสำคัญที่สุด/เป็นแก่นของโครงงาน ไปหาข้อรอง เช่น ข้อ 1 มักเป็น "เพื่อสร้าง/พัฒนา..." (แก่นของ
โครงงาน) ข้อถัด ๆ ไปเป็น "เพื่อทดสอบ/เปรียบเทียบประสิทธิภาพของสิ่งที่สร้าง"

## ตัวอย่างเต็ม: เขียนดี vs เขียนแย่ (ต่อจากตัวอย่างเครื่องรดน้ำอัตโนมัติ)

### ❌ เขียนแย่

> 1. เพื่อลดภาระของนักเรียนในการรดน้ำต้นไม้
> 2. เพื่อให้ผักสวนครัวเจริญเติบโตดี
> 3. เพื่อประหยัดน้ำและไฟฟ้า
> 4. เพื่อศึกษาการทำงานของเซนเซอร์ความชื้นในดินและวงจร Arduino ที่เชื่อมต่อกับปั๊มน้ำผ่านรีเลย์ โดยใช้ค่า
>    ความชื้นเป็นเกณฑ์ในการเปิด-ปิดปั๊มน้ำอัตโนมัติ

**ทำไมถึงแย่**: ข้อ 1-3 จริง ๆ แล้วเป็น "ผลลัพธ์/ประโยชน์" ที่จะตามมา ไม่ใช่สิ่งที่โครงงานลงมือทำโดยตรง
(โครงงานลงมือ "สร้างเครื่อง" ไม่ได้ลงมือ "ลดภาระนักเรียน" โดยตรง) — สามข้อนี้ควรย้ายไปเป็นประโยชน์ที่คาด
ว่าจะได้รับแทน ข้อ 4 ยาวเกินไปและลงรายละเอียดวิธีการ (รีเลย์, การเชื่อมต่อวงจร) ซึ่งเป็นหน้าที่ของขอบเขต/
วิธีดำเนินงาน ไม่ใช่วัตถุประสงค์

### ✅ เขียนดี

> 1. เพื่อออกแบบและสร้างเครื่องรดน้ำต้นไม้อัตโนมัติโดยใช้เซนเซอร์วัดความชื้นในดินเป็นตัวควบคุมการทำงาน
> 2. เพื่อทดสอบประสิทธิภาพของเครื่องรดน้ำต้นไม้อัตโนมัติในการรักษาระดับความชื้นในดินให้เหมาะสมกับการ
>    เจริญเติบโตของผักสวนครัว

**ทำไมถึงดี**: สองข้อนี้คือแก่นแท้ของสิ่งที่โครงงานลงมือทำจริง (สร้าง → ทดสอบ) แต่ละข้อสั้น กระชับ ระบุ "อะไร"
ไม่ใช่ "อย่างไร" และตอบปัญหาที่ยกไว้ในที่มาฯ ได้ตรงจุด (ปัญหาคือรดน้ำไม่สม่ำเสมอ → ข้อ 1 สร้างตัวช่วย →
ข้อ 2 พิสูจน์ว่าตัวช่วยนั้นได้ผลจริง)

## Checklist ก่อนถือว่าหัวข้อนี้เสร็จ

- [ ] ทุกข้อขึ้นต้นด้วย "เพื่อ" ตามด้วยกริยาที่ตรงกับสิ่งที่ทำจริง
- [ ] ไม่มีข้อไหนที่จริง ๆ แล้วเป็น "ผลลัพธ์/ประโยชน์" มากกว่า "สิ่งที่ลงมือทำ"
- [ ] ไม่มีข้อไหนลงรายละเอียดวิธีการ/สเปกอุปกรณ์ยาวเกินไป
- [ ] ไล่ทวนย้อนกลับไปที่ที่มาฯ ได้ทุกข้อว่าตอบปัญหาข้อไหน
- [ ] มีอย่างน้อย 3 ข้อ (ห้ามต่ำกว่านี้ เว้นแต่ผู้ใช้/สถาบันกำหนดเป็นอย่างอื่น) และไม่เกิน 5-6 ข้อ (ถ้าเกินให้
      พิจารณารวมข้อที่ซ้ำแก่น)
- [ ] ไม่มีข้อไหนซ้ำความหมายกับข้ออื่น
