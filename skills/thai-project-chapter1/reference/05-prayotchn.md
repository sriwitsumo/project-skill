# ประโยชน์ที่คาดว่าจะได้รับ — คู่มือเจาะลึก

## หน้าที่ของหัวข้อนี้ (และทำไมถึงมักเขียนซ้ำกับวัตถุประสงค์)

ตอบคำถาม: **"หลังโครงงานเสร็จ ใครได้อะไรบ้าง"** หัวข้อนี้คือจุดที่เขียนวกวนบ่อยที่สุดในทั้งเล่ม เพราะโครงสร้าง
ประโยคมันใกล้เคียงกับวัตถุประสงค์มาก คนเขียนจำนวนมากแก้ปัญหาด้วยการ **เอาวัตถุประสงค์มาเปลี่ยนแค่คำว่า
"เพื่อ" เป็น "ทำให้เกิด"** ซึ่งอ่านแล้วรู้สึกซ้ำทันที เช่น

- วัตถุประสงค์: "เพื่อออกแบบและสร้างเครื่องรดน้ำต้นไม้อัตโนมัติ"
- ประโยชน์ (เขียนแบบผิด): "ได้เครื่องรดน้ำต้นไม้อัตโนมัติ" ← นี่คือประโยคเดียวกัน แค่เปลี่ยนรูปกริยา ไม่ใช่
  ประโยชน์ใหม่

## หลักการที่แท้จริง: วัตถุประสงค์คือ "การกระทำ" ประโยชน์คือ "ผลกระทบต่อคน"

วัตถุประสงค์บอกว่า "โครงงานทำอะไร" ส่วนประโยชน์ต้องก้าวไปอีกขั้นและตอบว่า **"เพราะมีสิ่งนั้นแล้ว ชีวิต/
งาน/สภาพของใครเปลี่ยนไปอย่างไร"** เทคนิคที่ได้ผลที่สุดคือ **แบ่งประโยชน์ตามกลุ่มผู้ได้รับผลกระทบ (stakeholder)**
แทนที่จะไล่ตามลำดับวัตถุประสงค์ทีละข้อ วิธีนี้บังคับให้เกิดมุมมองใหม่โดยธรรมชาติ เพราะกลุ่มคนแต่ละกลุ่มได้
ประโยชน์คนละแบบจากสิ่งเดียวกัน

**กลุ่มผู้ได้รับผลกระทบที่พบบ่อย** (เลือกเฉพาะกลุ่มที่เกี่ยวข้องจริงกับโครงงาน):

1. **ผู้ใช้งาน/กลุ่มเป้าหมายโดยตรง** — ได้อะไรในชีวิตประจำวัน สะดวกขึ้นอย่างไร ประหยัดอะไรไป
2. **หน่วยงาน/สถาบันต้นสังกัด** (โรงเรียน ชุมชน) — มีอะไรเพิ่มขึ้น เป็นต้นแบบให้ใครได้ไหม
3. **คณะผู้จัดทำเอง** — ได้ทักษะ/องค์ความรู้อะไรเพิ่ม (ใส่ได้แต่ควรเป็นข้อรอง ไม่ใช่ข้อหลัก เพราะกรรมการ
   สนใจผลกระทบต่อภายนอกมากกว่า)
4. **วงวิชาการ/สาธารณะในวงกว้าง** — เป็นแนวทาง/ต้นแบบให้นำไปประยุกต์ใช้ต่อได้หรือไม่ (ใช้คำระมัดระวัง
   เป็นความคาดหวัง ไม่ใช่ยืนยันเกินจริง)

## เทคนิคเปลี่ยนวัตถุประสงค์ให้เป็นประโยชน์แบบไม่ซ้ำคำ

ใช้ 3 ขั้นนี้กับวัตถุประสงค์แต่ละข้อ:

```
ขั้น 1: ระบุว่าวัตถุประสงค์ข้อนี้ "สร้างอะไรขึ้นมา"
ขั้น 2: ถามว่า "สิ่งที่สร้างขึ้นนั้น ไปแก้ปัญหาที่เขียนไว้ในที่มาฯ ให้ใคร อย่างไร" (ย้อนกลับไปดูปัญหาตั้งต้น
        ไม่ใช่ย้อนไปดูตัววัตถุประสงค์)
ขั้น 3: เขียนประโยชน์จากมุมมองของคนที่ได้รับผล ไม่ใช่จากมุมมองของ "สิ่งที่ถูกสร้าง"
```

**ตัวอย่างการแปลง** (ต่อจากเครื่องรดน้ำอัตโนมัติ):

| วัตถุประสงค์ | ปัญหาตั้งต้นที่เกี่ยวข้อง (จากที่มาฯ) | ประโยชน์ที่แปลงแล้ว (มุมมองคนได้รับผล) |
|---|---|---|
| เพื่อออกแบบและสร้างเครื่องรดน้ำต้นไม้อัตโนมัติ... | ผักเหี่ยวเฉาเพราะขาดน้ำช่วงวันหยุด | แปลงผักสวนครัวของโรงเรียนได้รับน้ำอย่างสม่ำเสมอแม้ในวันหยุดที่ไม่มีนักเรียนมาดูแล ลดความเสียหายของผักที่เคยเกิดขึ้นเฉลี่ยสัปดาห์ละ 3-4 แปลง |
| เพื่อทดสอบประสิทธิภาพของเครื่อง... | นักเรียนไม่มีเกณฑ์ชัดเจนว่าควรรดน้ำเท่าไหร่ | นักเรียนที่รับผิดชอบแปลงผักลดภาระการจดจำตารางเวรและปริมาณน้ำที่ต้องรด สามารถใช้เวลาไปกับกิจกรรมการเรียนรู้ด้านอื่นของแปลงเกษตรได้มากขึ้น |

สังเกตว่าประโยชน์ทั้งสองข้อ **ไม่มีคำว่า "เครื่องรดน้ำอัตโนมัติ" ซ้ำเป็นประธานของประโยค** อีกต่อไป แต่เปลี่ยน
ประธานเป็น "แปลงผัก" และ "นักเรียน" แทน นี่คือกลไกหลักที่ทำให้ไม่ซ้ำกับวัตถุประสงค์

## คลังคำเปิดประโยคประโยชน์ (แยกตามกลุ่มผู้ได้รับผล)

- ผู้ใช้งานโดยตรง: "[กลุ่มเป้าหมาย] ได้รับความสะดวกในการ... / สามารถ...ได้โดยไม่ต้อง... / ลดระยะเวลาที่ใช้ใน..."
- หน่วยงานต้นสังกัด: "[หน่วยงาน] มีแนวทาง/ต้นแบบในการ...ที่สามารถนำไปประยุกต์ใช้กับ...ต่อไปได้"
- คณะผู้จัดทำ: "คณะผู้จัดทำได้รับความรู้และทักษะด้าน...เพิ่มเติมจากการลงมือปฏิบัติจริง"
- วงกว้าง/ผู้สนใจทั่วไป: "เป็นแนวทางเบื้องต้นสำหรับผู้ที่สนใจ...ในการนำไปพัฒนาต่อยอดในบริบทอื่น"

## ข้อผิดพลาดที่พบบ่อยนอกเหนือจากการซ้ำคำ

- **ประโยชน์เกินจริง**: เขียนว่าจะช่วยแก้ปัญหาระดับประเทศ/โลก ทั้งที่โครงงานทดสอบแค่ในพื้นที่เล็ก ๆ ให้ใช้คำ
  ที่แสดงขอบเขตความคาดหวังตามจริง เช่น "เป็นแนวทางเบื้องต้น" "อาจเป็นต้นแบบ" แทนการยืนยันเด็ดขาด
- **จำนวนข้อไม่ล้อกับวัตถุประสงค์**: ถ้าวัตถุประสงค์มี 2 ข้อ แต่ประโยชน์มี 6 ข้อโดยไม่มีที่มา แปลว่ากำลังเดา
  เอาเอง ให้ไล่ทวนแต่ละข้อกลับไปที่วัตถุประสงค์/ที่มาฯ เหมือนที่ทำกับหัวข้อวัตถุประสงค์
- **ประโยชน์คลุมเครือที่ใช้ได้กับโครงงานอะไรก็ได้บนโลก (ข้อผิดพลาดร้ายแรงที่พบบ่อยที่สุด)**: ห้ามเขียนประโยชน์
  ที่ไม่ได้ผูกกับเนื้อหาเฉพาะของโครงงานนี้เลย เช่น **"คณะผู้จัดทำได้พัฒนาความรู้"** หรือ **"คณะผู้จัดทำได้ใช้
  เวลาว่างให้เป็นประโยชน์"** ประโยคเหล่านี้ใช้แปะท้ายโครงงานเรื่องอะไรก็ได้โดยไม่ต้องเปลี่ยนคำเลยสักคำ จึงไม่
  นับเป็นประโยชน์ที่ "เกี่ยวข้องจริง" กับโครงงานนี้ — วิธีแก้คือต้องระบุ **ความรู้/ทักษะเรื่องอะไรกันแน่** ที่ได้จาก
  การลงมือทำโครงงานนี้โดยเฉพาะ เช่น จาก "ได้พัฒนาความรู้" ให้เปลี่ยนเป็น "คณะผู้จัดทำได้รับความรู้และทักษะ
  ด้านการเขียนโปรแกรมควบคุมไมโครคอนโทรลเตอร์และการประยุกต์ใช้เซนเซอร์วัดความชื้นในดิน" (ระบุเรื่องที่ได้
  จากโครงงานนี้จริง ไม่ใช่คำกว้าง ๆ ที่ใช้ซ้ำได้ทุกเล่ม) ถ้าเขียนแล้วอ่านได้ทุกโครงงานโดยไม่ต้องแก้คำ ให้ถือว่า
  เขียนผิดและต้องแก้ทันที

## Checklist ก่อนถือว่าหัวข้อนี้เสร็จ

- [ ] ไม่มีข้อไหนที่แค่เปลี่ยนรูปกริยาของวัตถุประสงค์ (เพื่อสร้าง → ได้เครื่อง)
- [ ] แต่ละข้อมีประธานของประโยคเป็น "คนที่ได้รับผล" ไม่ใช่ "สิ่งที่ถูกสร้างขึ้น"
- [ ] แบ่งตามกลุ่มผู้ได้รับผลกระทบชัดเจน ไม่ปนกันในข้อเดียว
- [ ] ไม่มีการอวดอ้างผลกระทบเกินขอบเขตของโครงงาน
- [ ] ไล่ทวนกลับไปหาวัตถุประสงค์/ที่มาฯ ได้ทุกข้อ
- [ ] ไม่มีข้อไหนเป็นประโยคคลุมเครือที่ใช้แปะกับโครงงานเรื่องอื่นได้โดยไม่ต้องแก้คำ (เช่น "ได้พัฒนาความรู้"
      "ได้ใช้เวลาว่างให้เป็นประโยชน์") — ทุกข้อต้องระบุเนื้อหา/ทักษะ/ผลกระทบที่เจาะจงกับโครงงานนี้เท่านั้น
